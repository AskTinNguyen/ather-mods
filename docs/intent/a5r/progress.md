## Engineering decisions (inside the intent's scope)

- E1 Grant vs sync: a grant's slot must end by the cutoff (T − 30), which satisfies both A3 ("fits before the next sync cutoff") and A5 ("grants that would cross the sync are deferred"); from the cutoff until done/abort only the sync holder is granted. The wait names the room left ("ask again for ≤ N min").
- E2 Launch gate (D5) applies only when no UnrealEditor runs; a FREE lock with the Editor still open is reused and its memory is already counted. PIE start 5 GB / abort 3 GB stay fixed. A missing RAM reading fails closed (the slot waits).
- E3 Liveness is conservative: a fresh Ather lane vouches for a session even if its hai-flow file is stale; a holder with neither file is unknown and its lease is never freed. Recovery writes `FREE … note=stale lease … background=unknown` (the gone holder cannot assert `none`).
- E4 Every hai-flow session with A5 on keeps a session file (heartbeat) even without a request, so "holder runs hai-flow" and "every A5 session" are file facts.
- E5 Panel presets for a sync: the first half hour ≥ 45 min ahead, then +1 h, +2 h (the cutoff notice still lands before its cutoff).
- E6 Launch gate control: one shared override in the plugin store (every session reads it) over the plugin options; the panel moves both gates together by 1 GB and Reset returns to the options; clamped to 10–60 GB.
- E7 "Main loop" for notices and busy/idle = `agentId === undefined && next.origin.plugin === 'engine'` (a plugin's own `$.tool.call` carries an engine-minted tool_use_id but its own origin).
- E8 Notice actionability: grant, yield, lease end/overrun/idle, gone-holder Editor, PIE abort, cutoff, release-by, holder's run-merge, conflicts, lift → actionable (one idle prompt); recovered lease, disk, freeze (non-holder) → wait for the next turn as context. A lift reaches only sessions told of that sync, within 6 h, and supersedes their pending cutoff/freeze notices.
- E9 Freeze scope: git writes whose repository root is the S2 shared checkout (main working tree), every Unreal MCP call and Editor start/stop; the sync holder and its workers are exempt; reads, other repositories and linked worktrees pass. `cd <worktree> && git …` still counts as the shared checkout (same limit as A5's git rules: use `git -C`).
- E11 (rev 4) Where the paused s2-sync-main skill differs from runbook-sync-lane, the worker follows A12 / the runbook: a binary conflict that is not a self-conflict aborts (the skill said "main wins"), `git merge --abort` is the worker's own step on such a conflict (the skill said report only), and a failed build is reverted with `git revert -m 1` (the skill said do not touch git).
- E12 (rev 4) The worker waits for an Editor another lane holds until 10 min before the hard end, then aborts, so its done/abort lands before the sync expires.
- E13 (rev 4) The freeze's `expired` is computed by every reader (hard end, or holder gone while frozen) and written by whichever session sees it first; one 🟥 per event through an alert file under `Saved/HaiFlow/alerts/` (sync expiry; a merge left behind, keyed by MERGE_HEAD's time). Before T a gone holder is still taken over (A5 behaviour kept).
- E14 (rev 4) The merge guard's "holder" is the holder of the last sync in any state, so it can still finish or abort its own merge after an expiry; everyone else waits for MERGE_HEAD to go.
- E15 (rev 5) Nghiệm thu A5 is triggered by the PR-opening call (gh pr create, gh api …/pulls POST) and by an intent's Status line closing; Ather's Ship hand-off has no observable event, so it is reached through the PR call it makes. Hai's pass-once covers that one call. Debug leftovers in docs (*.md, docs/) are not scored (docs may name console.log).
- E10 Rule-11 classification caps at 40 paths (each costs a rev-parse and a `git log --raw --max-count=200`); the rest count as foreign (the conservative side). No fetch before the dry-run (F-3).
- E16 (rev 18) After the fact, an old scorer's PR is recognised by its alert file (`pr-<n>.json` without `scorer`, not withdrawn): a pre-0.12.3 session file cannot tell the PRs it scored from those it only found listed, and only the scored-and-failed ones raised a 🟥; a PR the old path passed (no alert) is not scored again. The title's 🟥 itself is left to Hai (PENDING line ticked, alert withdrawn).
- E17 (rev 18) A merged or closed PR is read from `gh pr diff`, not from local refs: after a merge commit `origin/<base>...origin/<head>` is empty, which would pass it unread.
- E18 (rev 18) A single path longer than the card's text width (e.g. `.agents/skills/explicit-commit-pr/` at a 40-column desktop pane) can only break inside the path; the A53 test checks that items wrap and that each rule's name row fits, not that a path fits unbroken.
- E19 (rev 20) The release needs a fresh probe that names no Unreal Editor process at all, not only the lock's own pid: the lock line may say `pid=none` while an Editor runs (launched outside the lock); such a lease keeps its overrun notice and stays to Hai.
- E20 (rev 20) A55's "seen" is the holder's own `lastTurnAt` (its a5r writes it at turns, not at the minute timer) or its Ather lane's `lastActiveAt`; a holder whose a5r writes no turn time (before 0.13.0) is never judged unseen; A54 still releases its lease once lapsed. An unseen grant is passed on only while another session waits.
- E21 (rev 20) The releaser writes the holder's session file (its only write to another session's file): the holder may be gone, and the queue reads `holding`; a live holder's own a5r reads the `released` record at its next minute, drops its lease and request, and rewrites its file.
- E22 (rev 21) A PR enters acceptance by the checklist of the intent its diff is for, not always the tracked one: a PR opened from another worktree for another intent (A41's avatar-frame case) is judged by that intent's rows; a tracked intent is still required (none tracked: the PR runs). A47 (a)'s "most-named intent" and tie now show on demand (`/a5r accept`) only.
- E23 (rev 21) Before the checklist ends, after-the-fact scoring records the listed PR numbers as known, so a PR opened during Build is not scored the moment the last row turns met; only PRs listed after the end are.
- E24 (rev 22) Not fixed in this rev (from the review's list, no row): the lock line's pid is written only at the grant (`pid` of an Editor already open) and at an extension (`lock.pid ?? editorPid(probe)`); an Editor launched after the grant leaves `pid=none`, so "pid=none" does not prove no Editor ran (A58 checks every Unreal process instead). An extension is refused once the lease has ended, so a live holder past its end can only release and ask again.
- E25 (rev 22) A62's candidate lines are logged once per lease and rule by the first session to claim them (alert files `log-…`), so concurrent sessions do not repeat a line; appends are read-modify-write, so two sessions appending in the same instant can lose one line (accepted for a measurement log). "Running agents" is the holder's own count from its session file (absent for an a5r older than 0.13.1).
