## ★ A5 is ON: five rules on top of Ather's intent flow (conflicts: 5 > 1 > 3 > 2 > 4)
The intent skill and Ather's loop (Plan, Build, Prove, Ship; findings; away window) come first; A5 adds checks to them and never replaces a step. When they are checked: [H] at the tool call, only for what cannot be undone; [N] at nghiệm thu A5 (acceptance), right before a PR is opened and when an intent closes, over the whole branch (diff against main), the intent's files and Ather's proof; [P] practice, nobody checks it. Nothing is checked per turn: there is no end-of-turn report to write.
- 1 Yêu Project, yêu đồng bào (keep shared state and other sessions' work safe) [H] In the shared checkout, git that discards work (reset --hard, clean -f, checkout/restore/stash that drop changes) or moves the tree (switch, checkout <branch>), and edits to repository config (*.uproject, *.Build.cs, *.Target.cs, Config/*.ini, root .gitignore/.gitattributes/AGENTS.md/CLAUDE.md) need Hai's approval in a dialog; inside a worktree of your own (`git -C <worktree> …`) they are yours. Everywhere: force push, push to main, `git add .`, recursive deletes outside temp folders and settings.json need approval. `--no-verify`, `GIT_LFS_SKIP_SMUDGE=1`, `git sparse-checkout set` in the shared checkout, and edits to the a5 mod are refused (Hai turns A5 off to let the mod be edited). The Editor holder, RAM and Sync main below are this rule's tools. [N] No path another live session is editing (its touch file) or another intent names; nothing straight onto main. A worker (subagent) is never asked: the call is refused, and the worker leaves it undone, stops and reports it.
- 2 Học tập tốt, lao động tốt (understand before acting, finish to proof) [P] Read the target and one call site before editing. [N] Every Acceptance row marked `met` in progress.md carries its evidence (the command and its result line); Ather's proof is complete for the role; every new TODO/FIXME is listed in progress.md or findings.md.
- 3 Đoàn kết tốt, kỷ luật tốt (right role, right scope, right channel) [P] One writer per intent file; coordination goes through A5 notices; out-of-scope work becomes a finding, unfixed. [H] With a scope file (`rules/scope` in the mod), edits outside it need approval. [N] The diff stays within the paths the intent names (backticked repo paths in prompt.md, plus its own `docs/intent/<slug>/`); any other path is explained in progress.md or findings.md. Without an intent: shared config changed is named in the PR body.
- 4 Giữ gìn vệ sinh thật tốt (leave it clean) [H] Secrets in edits are refused. [P] Tag temporary debug lines `A5TMP`; release the Editor with its release line. [N] No debug leftovers (`A5TMP`, console.log, debugger, breakpoints) or secrets in the diff, no untracked file left in the shared checkout, no second worktree on the branch, no background agent of this session still running.
- 5 Khiêm tốn, thật thà, dũng cảm (claim only what was measured) [H] Removing test assertions needs approval. [P] An Unreal build counts only by its own `Result:` line (Build.bat exits 0 on failure; never pipe it to tail); label claims MEASURED / INFERRED / WITHDRAWN; say FAILED; never loosen the DoD; raise 🟥 or abort when stuck. [N] The PR body claims no proof rung that Ather has not read pass (and says FAILED for one that failed); no row is `met` while its evidence says it is not done; no acceptance row is rewritten without a new rev.

Nghiệm thu A5: opening a PR (`gh pr create`, `gh api …/pulls` POST) or closing an intent (its prompt.md gains `- Status: closed`) runs the score first. A rule not met refuses the call with the list `- <rule>: <file>: <what> → <what to do>`: fix them and open the PR again. Hai can let one through in the dialog; a worker is refused and reports the list. `/a5 accept` scores the branch now without opening anything; the pane shows the card.

## Coordination: the shared Editor, RAM and Sync main (A5)
Sessions on this machine share one S2 checkout and one Editor. a5 coordinates them from files under the checkout's `Saved/A5/` (the truth; nothing in git).
- Editor holder: the tool `mcp__a5__editor` is the only way to take or give the Editor. `request` (minutes, pie, build, what): sessions are served in the order they asked; a slot ends before the next sync's cutoff; launching needs the RAM launch gate (the safe cleanup runs first). `release` when done (stop PIE and every background process of yours that could call MCP first; list packages to discard in `dont_save`). `extend` before your lease ends, if it still fits. `status` reads the holder, the queue, RAM and the next sync. Never write Saved/EDITOR_OWNER.txt yourself (refused). PIE, saves, Editor start/stop and Unreal MCP calls need this session on the lock (`session {SESSION8}`). PIE starts only with 5 GB free (fixed); under 3 GB stop it. Never save-all. While you wait, do the work that needs no Editor.
- Sync main: a merge of origin/main is planned on the A5 panel, with `/a5 sync HH:MM [build]`, or with the tool `mcp__a5__sync` (plan, move, build, cancel, conflicts, done, abort, status); only its holder changes it. At the cutoff (sync − 30 min) commit your own paths with exact paths, write your resume note in `Saved/LANE_NOTES/<session id>.md`, stop PIE and release the Editor by sync − 10; keep `Source/` and `Plugins/` edits out of the shared tree. From the sync time, git writes and Editor use in the shared checkout are refused for every session but the holder until done or abort, at the latest until the hard end (sync + 45 min, + 90 with a build) or as soon as the holder session is gone; then the sync expires and Hai is asked. Never stash, reset or discard your work to get past it; work without git or in your own worktree. While `.git/MERGE_HEAD` exists in the shared checkout, git writes there stay refused for everyone but the sync's holder, whatever the sync says: leave a merge alone. A conflict notice names your paths: a self-conflict needs nothing; a foreign one is yours to commit and explain before the sync (a logic or .uasset/.umap conflict aborts the merge and comes back to you). An untracked file of yours that origin/main adds blocks the merge: commit it or move it out of the tree before the sync, never delete a file that may be someone else's. At the sync time the holder's a5 starts the sync worker (a background agent of the holder session), which runs the merge and ends it with done or abort; the holder leaves git and the Editor to it and never starts that worker itself.
- Messages that start with `A5 ·` come from this coordination layer, addressed to this session (a grant, a yield request, a lease end, a sync cutoff, a conflict, a freeze or its lift): act on what follows the arrow. Never copy them into docs/intent files (progress, findings, log): such an edit is refused.

Refusals from a5 read `A5 · <gate> — <why> → <what next>`: do what follows the arrow; do not retry the same call.
