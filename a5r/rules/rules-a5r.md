## ★ A5R is ON: five rules on top of Ather's intent flow (conflicts: 5 > 1 > 3 > 2 > 4)
The intent skill and Ather's loop (Plan, Build, Prove, Ship; findings; away window) come first; A5R adds checks to them and never replaces a step. When they are checked: [H] at the tool call, only for what cannot be undone, on measured facts (A5R never asks and never waits: a call runs, or it is refused with what to do instead; bypass mode and an away window change nothing); [N] at A5R acceptance (nghiệm thu), right before a PR is opened and when an intent closes, over the whole branch (diff against main), the intent's files and Ather's proof; [P] practice, nobody checks it. Nothing is checked per turn: there is no end-of-turn report to write.
- 1 Love the project, love your fellow sessions (keep shared state and other sessions' work safe) [H] In the shared checkout, git that can discard work on exact paths (`checkout <ref> -- <paths>`, `restore <paths>`, `stash push -- <paths>`, `clean -f -- <paths>`, `rm <paths>`, from whatever folder you `cd` into) runs when those paths have no uncommitted change, or only changes in paths your session's touch file lists and no other live session claims; otherwise it is refused naming each path and its owner: commit or move it first (its owner does), or work in a worktree of your own. Name exact paths: a discard with no paths, `.`, a whole top folder, a variable or a pattern is refused with the same command on exact paths (a status of the whole S2 tree takes over half a minute); `reset --hard` is refused (use `checkout <ref> -- <paths>`). Refused with the alternative in the shared checkout: moving the tree (`switch`, `checkout <branch>`, `checkout -b/-B`), `clean -x/-X` (Saved/, Intermediate/, Binaries/ are ignored, not unused), `stash pop/apply` (apply it in a worktree), `stash drop/clear` while entries exist, `apply -R`, `worktree remove --force`, `branch -D`, `submodule update --force`. Edits to repository config (*.uproject, *.Build.cs, *.Target.cs, Config/*.ini, root .gitignore/.gitattributes/AGENTS.md/CLAUDE.md, settings.json), recursive deletes, other global git config and `p4 revert/delete` run and are recorded for A5R acceptance. Inside a worktree of your own (`git -C <worktree> …`) git is yours. Refused with the alternative everywhere: force push and push to main (push a branch, open a PR), `git add .`/`-A` (add exact paths), `--no-verify` (fix what the hook reports), `GIT_LFS_SKIP_SMUDGE=1` (let LFS fetch), `git sparse-checkout set` in the shared checkout (a worktree of your own), `git config --global` for credential.*, lfs.*, core.autocrlf/eol/hooksPath/fsmonitor, filter.* (`git config --local`, or `git -c`), `p4 obliterate` (`p4 delete`), and writes into the live a5r plugin folder (change the mod in a worktree of its repository; reads, tests and builds there run). The Editor holder, RAM and Sync main below are this rule's tools. [N] No path another live session is editing (its touch file) or another intent names; nothing straight onto main. A worker (subagent) gets the same answers as the main loop.
- 2 Study well, work well (understand before acting, finish to proof) [P] Read the target and one call site before editing. [N] Every Acceptance row marked `met` in progress.md carries its evidence (the command and its result line); Ather's proof is complete for the role; every new TODO/FIXME is listed in progress.md or findings.md.
- 3 Unity and discipline (right role, right scope, right channel) [P] One writer per intent file; coordination goes through A5R notices; out-of-scope work becomes a finding, unfixed. [H] With a scope file (`rules/scope` in the mod), edits outside it run and are recorded. [N] The diff stays within the paths the intent names (backticked repo paths in prompt.md, plus its own `docs/intent/<slug>/`); any other path is explained in progress.md or findings.md. Shared config changed is named in the PR body.
- 4 Keep it clean (leave it clean) [H] Secrets in edits are refused. [P] Tag temporary debug lines `A5RTMP`; release the Editor with its release line. [N] No debug leftovers (`A5RTMP`, the old `A5TMP`, console.log, debugger, breakpoints) or secrets in the diff, no untracked file left in the shared checkout, no second worktree on the branch, no background agent of this session still running.
- 5 Modest, honest, brave (claim only what was measured) [H] Removing test assertions runs and is recorded. [P] An Unreal build counts only by its own `Result:` line (Build.bat exits 0 on failure; never pipe it to tail); label claims MEASURED / INFERRED / WITHDRAWN; say FAILED; never loosen the DoD; raise 🟥 or abort when stuck. [N] The PR body claims no proof rung that Ather has not read pass (and says FAILED for one that failed); no row is `met` while its evidence says it is not done; no acceptance row is rewritten without a new rev; test assertions removed at the action, and every other recorded action of yours (deletes, config, Perforce), are named with a reason in progress.md or findings.md.

A5R acceptance (nghiệm thu): opening a PR (`gh pr create`, `gh api …/pulls` POST, or any MCP tool that creates a pull request, e.g. `mcp__github__create_pull_request`) or closing an intent (its prompt.md gains `- Status: closed`) runs the score first. A rule not met refuses the call with the list `- <rule>: <file>: <what> → <what to do>`: fix them and open the PR again; nothing waits on an answer (Hai lets one through beforehand with `/a5r pass <slug or PR>`). A branch diff (against origin/main) that cannot be read whole is no pass: the call is refused with why; open the PR from a slice branch cut from origin/main. When Ather hands you its Ship prompt, a5r adds the intent's score to it: fix what it lists before you open the PR. A PR opened outside the agent is scored after the fact once its number is on the intent's `- PR:` line, and a failing one is a 🟥 for Hai. `/a5r accept` scores the branch now without opening anything; the A5R pane (`/a5r`, or A5R › in Ather's pane) shows the card.

## Coordination: the shared Editor, RAM and Sync main (A5R)
Sessions on this machine share one S2 checkout and one Editor. a5r coordinates them from files under the checkout's `Saved/A5R/` (the truth; nothing in git).
- Editor holder: the tool `mcp__a5r__editor` is the only way to take or give the Editor. `request` (minutes, pie, build, what): sessions are served in the order they asked; a slot ends before the next sync's cutoff; launching needs the RAM launch gate (the safe cleanup runs first). `release` when done (stop PIE and every background process of yours that could call MCP first; list packages to discard in `dont_save`). `extend` before your lease ends, if it still fits. `status` reads the holder, the queue, RAM and the next sync. Never write Saved/EDITOR_OWNER.txt yourself (refused). PIE, saves, Editor start/stop and Unreal MCP calls need this session on the lock (`session {SESSION8}`). PIE starts only with 5 GB free (fixed); under 3 GB stop it. Never save-all. While you wait, do the work that needs no Editor.
- Sync main: a merge of origin/main is planned on the A5R panel, with `/a5r sync HH:MM [build]`, or with the tool `mcp__a5r__sync` (plan, move, build, cancel, conflicts, done, abort, status); only its holder changes it. At the cutoff (sync − 30 min) commit your own paths with exact paths, write your resume note in `Saved/LANE_NOTES/<session id>.md`, stop PIE and release the Editor by sync − 10; keep `Source/` and `Plugins/` edits out of the shared tree. From the sync time, git writes and Editor use in the shared checkout are refused for every session but the holder until done or abort, at the latest until the hard end (sync + 45 min, + 90 with a build) or as soon as the holder session is gone; then the sync expires and Hai is asked. Never stash, reset or discard your work to get past it; work without git or in your own worktree. While `.git/MERGE_HEAD` exists in the shared checkout, git writes there stay refused for everyone but the sync's holder, whatever the sync says: leave a merge alone. A conflict notice names your paths: a self-conflict needs nothing; a foreign one is yours to commit and explain before the sync (a logic or .uasset/.umap conflict aborts the merge and comes back to you). An untracked file of yours that origin/main adds blocks the merge: commit it or move it out of the tree before the sync, never delete a file that may be someone else's. At the sync time the holder's a5r starts the sync worker (a background agent of the holder session), which runs the merge and ends it with done or abort; the holder leaves git and the Editor to it and never starts that worker itself.
- Messages that start with `A5R ·` come from this coordination layer, addressed to this session (a grant, a yield request, a lease end, a sync cutoff, a conflict, a freeze or its lift): act on what follows the arrow. Never copy them into docs/intent files (progress, findings, log): such an edit is refused.

Refusals from a5r read `A5R · <gate> — <why> → <what next>`: do what follows the arrow; do not retry the same call.
